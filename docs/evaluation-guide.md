# 检索评测说明

本项目已经有评测入口，但评测结果是否有意义，取决于是否准备了人工标注的查询集。评测不是为了追求漂亮数字，而是为了说明 Agent、多模态标签、重排策略确实比单纯 CLIP 更稳定。

## 评测文件

示例文件：

- `data/eval_queries.example.json`

建议复制并填写：

- `data/eval_queries.json`

每条查询建议包含：

```json
{
  "query": "海边的人像照片",
  "library": "personal",
  "relevant_ids": ["asset_xxx", "asset_yyy"],
  "note": "用于测试场景+人物语义"
}
```

字段说明：

- `query`：用户会真实输入的自然语言。
- `library`：`all/public/personal`。
- `relevant_ids`：人工认为正确的素材 ID。
- `note`：可选，说明这条查询测什么能力。

## 建议覆盖的查询类型

- 单物体：猫、车、食物、海边。
- 场景：室内会议、街景、夜晚、雪天。
- 人物：已命名人物、未命名 `person_000x`。
- 人物关系：`person_0001 在 person_0002 左边`。
- 视觉关系：猫在车上、猫在车底、人坐在桌前。
- OCR：画面里有某段文字。
- ASR：视频里说到某个词。
- 文档：包含接口规范的文档、关于 OCR 的说明。
- 组合条件：个人库中，某个人，在海边，带文字。

## 评测指标

系统当前关注：

- `Recall@1`：第一条是否命中正确结果。
- `Recall@5`：前 5 条是否至少命中一个正确结果。
- `Recall@10`：前 10 条是否至少命中一个正确结果。
- `MRR`：第一个正确结果越靠前越好。
- `avg_latency_ms`：平均搜索耗时。

答辩时建议重点讲 `Recall@5` 和 `MRR`。因为素材检索不是分类题，用户通常会看一组结果，而不只看第一张。

## 对比方案

当前评测面板对比：

- `clip_only`：只看 CLIP 图文向量相似度。
- `clip_tags`：CLIP + 标签增强。
- `agent_v3`：Agent 解析 + 多路召回 + 标签/文本/关系重排。

如果 `agent_v3` 在复杂查询上明显更好，就能说明 Agent 的价值不是“包装概念”，而是实际改善组合语义检索。

## Web 评测

打开系统页，点击“检索评测”。如果没有 `data/eval_queries.json`，系统会提示使用示例或缺少人工标注。

适合演示：

- 展示三种方案对比。
- 展示复杂查询下 Agent 的优势。
- 展示延迟，说明系统是否仍然可用。

## 命令行评测

如果需要生成更稳定的报告，可以用工具脚本评测并保存输出。建议 D 负责维护查询集，A 负责解释不同方案的差异。

评测完成后，可将关键结果整理进技术报告：

- 数据集规模。
- 查询条数。
- 各方案 Recall@5/MRR。
- 典型成功案例。
- 典型失败案例和改进方向。
