# 演示与联调检查清单

这份清单用于组内联调、课堂展示和答辩前自查。目标是保证现场不靠临时发挥。

## 启动前检查

- 服务能打开：`http://127.0.0.1:8000`
- 校园网访问时，确认同学使用的是本机局域网 IP，而不是 `127.0.0.1`。
- `/api/status` 中 `asset_count` 和 `indexed_count` 接近或相等。
- 素材库能看到图片、视频、文档。
- 视频封面比例正常，不撑乱素材库列表。
- 个人库和公共库筛选能正常切换。

## 建议演示流程

1. 上传素材：选择公共库或个人库，上传图片/视频/文档。
2. 素材库浏览：展示图片、视频、文档统一管理。
3. 普通搜索：搜索“海边”“食物”“车”等基础语义。
4. 复杂搜索：搜索“猫在车上”“人在桌子旁边”等组合语义。
5. 人物搜索：搜索已命名人物，展示从 `person_000x` 到真实名字的映射。
6. 人物管理：展示人物命名、合并、删除。
7. OCR/ASR：打开视频或带文字图片，展示文本信号和标签。
8. 文档搜索：搜索“接口规范”“OCR”“评测”等文档内容。
9. Agent Trace：展示 Agent 如何拆解查询和重排结果。
10. 检索评测：展示 `clip_only`、`clip_tags`、`agent_v3` 对比。

## 推荐准备的查询

提前准备一组能稳定命中的查询，不建议现场完全随机输入：

- “海边照片”
- “有食物的图片”
- “公共库里的动物”
- “个人库里某某的照片”
- “person_0001 在 person_0002 左边”
- “画面里有英文字幕的视频”
- “提到 OCR 的文档”
- “关于接口规范的材料”

## 常见问题

### 搜索分数为什么不是 90% 以上？

CLIP 相似度不是传统百分制，它更像向量空间里的相对距离。前端展示的 `display_score` 是便于用户理解的归一化分数，不应当和考试分数直接类比。

### 为什么人脸分组偶尔不准？

人脸聚类依赖检测质量、图片清晰度、角度、遮挡和阈值。系统已经支持命名、合并、删除和单素材移除人物标签，实际产品也通常需要用户轻量校正。

### 为什么视频第一次打开慢？

视频文件比图片大，浏览器会请求视频元数据或分段内容。列表页应只加载封面，详情页再加载播放器。

### 为什么文档没有命中？

可能原因：

- 文档是扫描版 PDF，没有可提取文本。
- 文档内容太短，语义不明显。
- 文档刚上传但索引未更新。
- 查询词和文档表达差异太大，需要 Agent 改写或文档切片增强。

## 答辩重点

- 不是只做了关键词搜索，而是 CLIP 跨模态检索 + Agent 条件拆解 + 多路融合重排。
- 不只是图片，已经扩展到视频、OCR/ASR 文本、文档。
- 不只是算法脚本，已经有素材库、人物管理、标签管理、任务面板、评测面板。
- 团队接口清晰：B/C 可以输出模块结果，A/D 负责统一入库和检索，E 负责可视化和演示体验。
