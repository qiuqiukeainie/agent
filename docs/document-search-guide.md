# 文档检索说明

系统已经支持把文档作为素材库的一类资产接入，目标是让图片、视频、文档都能进入统一检索入口。

## 支持格式

当前支持：

- `.pdf`
- `.docx`
- `.pptx`
- `.txt`
- `.md`

上传入口与图片、视频相同，选择公共库或个人库后上传即可。

## 文档如何参与搜索

文档入库时会走以下流程：

1. 识别文件类型为 `document`。
2. 从文档中提取正文文本。
3. 将正文写入文本信号，来源标记为 `document`。
4. 根据正文生成文档标签。
5. 使用 CLIP 文本编码生成文档向量。
6. 搜索时与图片、视频一起参与统一召回和重排。

这意味着用户可以直接搜索：

- “包含项目分工的文档”
- “讲 OCR 和 ASR 的材料”
- “有检索评测指标的报告”
- “关于人脸聚类接口的说明”

## 与图片/视频搜索的区别

图片和视频主要依赖视觉向量、标签、OCR/ASR 文本；文档主要依赖正文文本和文档标签。

目前文档搜索返回的是“整份文档”，不是文档内某一页或某一段。后续如果要做得更专业，可以升级为“文档切片检索”：

- 按段落、页码或幻灯片切片。
- 每个切片单独生成向量。
- 搜索结果显示命中的页码、段落摘要和高亮词。
- 点击结果后跳到对应文档位置。

## 扫描版 PDF 的限制

如果 PDF 是扫描图片，不包含真实文本，普通 PDF 文本提取可能拿不到正文。这类文件需要 OCR：

- 先把 PDF 页面渲染成图片。
- 对页面图片运行 OCR。
- 将 OCR 结果作为 `document` 或 `ocr` 文本信号写入。

这可以作为 C/D 后续升级点。

## 建议的团队分工

- A：让 Agent 能识别“查文档”“查图片”“查视频”“全库搜索”等意图。
- C：负责文档 OCR、扫描 PDF 文本提取、文档摘要。
- D：负责文档切片、向量索引、元数据结构。
- E：负责文档列表、文档详情、命中摘要和下载/打开入口。

## 后续升级路线

优先级建议：

1. 文档切片检索：解决长文档只返回整篇的问题。
2. 命中摘要：搜索结果展示“为什么命中”。
3. 扫描 PDF OCR：覆盖真实材料中常见的图片 PDF。
4. 文档问答：基于命中文档片段回答问题，并列出引用来源。
5. 跨模态关联：搜索“和这份报告相关的演示视频/图片素材”。
